# 2026-10-20 提示词预设：导入 / 切换 / 导出（v0.3.24）

## 一句话

「自定义提示词」从五个手填槽位，升级为**可导入、可切换、可导出的具名预设**：把社区世界书
（或任意来源的规则文档）经外部 AI 按 `文生图转换说明书/文生图转换说明书.md` 转成 JSON 后，
点「导入」即可整组启用，随时切回内置默认。

---

## 为什么这么做

### 需求来源

用户希望直接使用社区「文生图世界书」，替代插件自带的五份提示词；并且要能多套切换。

### 关键判断：槽位 ≠ 世界书

- 槽位（`settings.autoTag.prompts`）是**固定拼装顺序、无条件生效、不做宏替换**的纯文本，
  拼装点只有两处：`src/autoTag/prompt.ts` 的 `backendPromptSpec` / `backendThinkingPrompt`
  （jailbreak 另在 `buildMessages` 里置顶）。
- 世界书是**关键词激活 + 位置/深度可配**的条目集，由 ST 侧装配；条目里常含 `<START>`、`{{user}}`、EJS。

结论：**不能让槽位直接读世界书**。会引入激活语义、宏残留、以及「这本书挂没挂」导致的行为漂移。

### 被否掉的方案

| 方案 | 否决理由 |
| --- | --- |
| 运行时读世界书（`loadWorldInfo`） | 依赖本地挂载、跨设备不同步；与现有「排除世界书」逻辑互相干扰；WI 更新会让出图行为静默改变 |
| 在代码里写各社区书的适配器 | 格式无穷无尽，维护成本落在代码上；每来一本新书就要发版 |
| 预设 = 增量补丁（只写差异，叠加在内置之上） | 需要一套 diff/合并语义，改一处内置就得重算所有补丁，复杂度远超收益 |

**选定方案：具名快照 + 外部 AI 转换 + 导入时强校验。**
预设存全量五槽位；`settings.autoTag.prompts` 仍是**唯一生效源**，切换 = 把快照写进去。
好处：`prompt.ts` 一行都不用改，不存在两份真相；导入后与来源脱钩，行为可复现、可回退、可分享。

## 改了什么

### 新增 `src/state/promptPreset.ts`（核心逻辑，纯函数）

- 类型：`PromptPreset { id, name, backend, prompts, basedOn, notes, createdAt }`；
  文件协议 `kind = 'bbi-prompt-preset'`、`schemaVersion = 1`。
- `parsePromptPresetFile(text)`：解析 + 校验，任一条不过整体拒绝（错误信息中文、可执行）。
- `normalizePromptPresets / normalizePresetPrompts`：存量兜底（无名丢弃、重复 id 重编、非法 backend 回退）。
- `buildPromptPresetFile`：导出（空槽位不写，保持文件可读）。
- `promptsEqual / presetSlotSummary / checkNlSections`：脏标记、确认弹窗摘要、条件段配对检查。
- 上限：单槽位 12000 字符、预设 50 条、文件 2 MB。

**校验规则（重要，别随手放宽）**：

1. `kind` / `schemaVersion` / `backend` 三关，且 `backend` 必须与所填槽位匹配
   （comfyui 却只填 NAI 槽位 → 导入后完全不生效，这是最难查的失败，直接拦）。
2. 未知槽位键报错（防拼错键静默丢内容）。
3. ST 宏（`{{user}}` / `{{char}}` / `{{getvar}}`）、EJS（`<%`）、`<START>` 一律拒。
4. `{{#nl}}` / `{{^nl}}` 必须与 `{{/nl}}` 成对，且不允许嵌套（解析端是非贪婪正则，嵌套会静默吞半段）。
5. `{{nl}}` 只允许出现在 `comfySpec`，最多一次。
6. 块协议标记（`image###` / `<shot>` / `<ledger>` / `<bbi_image>`）**分两种情形**：
   出现在行首（模板排版）或与「输出/写入/返回」类动词同句且无否定词 → 拒；
   出现在否定句或「历史标记只作线索」这类引用里 → 放行。
   （内置思维链本身就有「历史 `<bbi_image>` 只作连续性线索」一句，不能一刀切。）

### 修改 `src/state/settings.ts`

- `AutoTagSettings` 增加可选字段 `promptPresets?: PromptPreset[]`、`activePresetId?: string`。
  **设为可选**是为了不破坏既有测试里手写的 `AutoTagSettings` 字面量。
- `defaults()` 补 `promptPresets: []` / `activePresetId: ''`。
- `normalize()` 里先 `normalizePromptPresets`，再校验 `activePresetId` 是否指向存在的条目
  （悬空 id 会让下拉显示空白、且「保存」写不回任何东西，必须归零）。

### 修改 `src/pages/settings/index.vue`

「自定义提示词」折叠区顶部新增预设条：

- 下拉：`内置默认` + 全部预设；切换即整组写入槽位。
- 按钮：保存（写回当前预设）/ 另存为 / 导入 / 导出 / 删除。
- 状态：`当前槽位已改动，尚未写回预设`（`promptsEqual` 实时比较）；操作结果提示（错误转危险色）。
- 三个新弹窗：另存为、导入确认（显示名字/口径/各槽位字符数/来源说明）、删除确认；
  另有一个「带未保存改动切换预设」的丢弃确认。
- 新增 CSS：`.bbi-preset-actions`、`.bbi-field-hint.is-warn`。

**交互上的两个刻意选择**：

- 改槽位**不自动写回**预设 —— 写回是显式动作，否则「先改改看」会污染预设。
- 删除预设**只解绑不清空槽位** —— 用户可能只是想脱离预设继续手改。

### 新增 `docs/presets/build-preset.mjs` + `docs/presets/分镜导演_ComfyUI_v1.json`

- 第一份随包预设：由「分镜师系统_世界书」改写，ComfyUI 口径。
- **为什么用脚本生成而不是手写**：预设是**整体替换**内置规范（`comfySpec` 非空即不再拼内置），
  所以预设必须自带内置规范的全部硬约束（同人身份 tag 转义、多人绑定、画面补全、景别一致性）。
  脚本直接从 `settings.ts` 抽取 `DEFAULT_COMFY_SPEC` / `DEFAULT_COMFY_THINKING` 原文再追加分镜增强，
  保证两者不会漂移。改动内置文本后重跑 `node docs/presets/build-preset.mjs` 即可。
- 结果：`comfySpec` 9340 字符、`comfyThinking` 5467 字符（每楼都会发送，成本需留意）。

### 新增测试

- `src/state/promptPreset.test.ts`：24 例，覆盖协议、宏、条件段、槽位匹配、超长、往返导出。
- `src/state/presets.shipped.test.ts`：用 `import.meta.glob` 扫 `docs/presets/*.json`，
  保证随包预设一定过得了导入校验（避免「用户点导入才看到报错」）。

## 遗留 / 下一步

1. **未实测**：本次只做了单测与构建，尚未在酒馆里跑真实楼层。重点看三件事：
   - 5 张上限下，模型是否按「选拍打分」给出 5 个不同景别；
   - 双人场景是否按角色分段绑定（串色是这套书最容易翻车的地方）；
   - 每楼 14.8k 字符提示词的 token 成本是否可接受（可对比请求历史里的 usage）。
2. **没有「精简版」预设**：完整版为了不丢内置约束而较长。若成本过高，下一步做
   「分镜增强 + 内置硬约束摘要」的精简版（目标 5–6k 字符），但必须逐条对照内置规则，不能漏。
3. **张数仍需手动设**：预设不管张数（规范里不写张数是刻意的，避免与设置打架）。
   用 5 张请到「自动生成 tag → 单楼最多图片数」改 5。
4. **`configTransfer` 未单独处理**：预设随 `settings` 整体导出/导入（`deepMergeDefined` 会整组替换数组），
   语义可接受但未写测试。若以后要做「只导出预设」，再单独加。
