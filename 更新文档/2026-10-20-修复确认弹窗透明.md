# 2026-10-20 修复聊天侧确认弹窗透明（v0.3.26）

## 一句话

楼层「重新生成 tag」的确认弹窗背景与遮罩全透明、文字与聊天内容叠在一起。根因是
`modalHost` 这个 Teleport 宿主**从未被赋值**，弹窗退化成原地渲染，落在 `.bbi-root` 之外，
取不到 `--bbi-*` 主题变量。

## 为什么会出现

`state/ui.ts` 导出 `modalHost = ref<HTMLElement | null>(null)`，App.vue 里有一个
`<div ref="modalHost"></div>`。旧版 App.vue 同时 `import { modalHost } from '@/state/ui'`，
靠「模板 ref 同名绑定到导入的 ref」这条隐式链路把 DOM 赋进去。

v0.3.23 的清理提交 `63e08e0` 把这条导入判成「多余」（它在脚本里确实没被引用），删掉了。
后果链条：

1. 模板里 `ref="modalHost"` 找不到同名绑定 → 不赋值 → `modalHost` 永远是 `null`；
2. 所有 `Teleport :to="modalHost" :disabled="!modalHost"` 都走 `disabled` 分支 → 原地渲染；
3. 聊天侧的命令式确认窗（`components/confirm.ts` 挂进 shadow root 的容器）落在 `.bbi-root` **之外**；
4. `--bbi-bg` / `--bbi-line` 等变量只在 `.bbi-root[data-theme]` 上定义 → 弹窗 `background: var(--bbi-bg)` 失效 → 透明。

设置页里的弹窗看起来正常，是因为它们原地渲染时仍在 `.bbi-root` 内，变量取得到 ——
只有「聊天侧呼出」这一条路径会暴露。

## 改了什么

`src/App.vue`：

- 重新引入 `modalHost`，新增 `modalHostEl` ref 与显式赋值：

```ts
const modalHostEl = ref<HTMLElement | null>(null);
onMounted(() => { modalHost.value = modalHostEl.value; });
onUnmounted(() => { modalHost.value = null; });
```

- 模板 `<div ref="modalHost">` → `<div ref="modalHostEl">`。
- 在赋值处写了长注释，说明**为什么不能靠同名导入自动绑定**：模板 ref 是字符串，
  编译器不会为它生成对导入变量的引用，打包时该导入会被摇掉。

## 怎么验证

```bash
npx vitest run     # 899 passed / 3 skipped
npm run build      # 通过
```

界面：聊天里点某楼「⋯ → 调色板（生成生图 tag）」，已出过图时会弹确认窗 —— 应有
不透明卡片 + 半透明遮罩，不再是文字叠加。插件窗口开着/关着两种情况都要看（开着时
Teleport 到 modalHost 浮在窗口之上，关着时同样）。

## 遗留 / 下一步

- 这类「模板 ref 与导入同名」的隐式依赖极脆弱，已记入 `MAINTENANCE.md` §4.1 的误删清单。
  以后清理未用导入时，必须同时 grep 模板里的 `ref="名字"`。
- 未加自动化回归：现有测试环境没有真实 DOM 挂载 App.vue，补它成本高于收益。
  若要防回归，可在 `index.ts` 初始化后断言 `modalHost.value !== null` 并在控制台告警。

## 回滚

把 `modalHostEl` 相关代码删掉、模板改回 `ref="modalHost"` 即可回到「透明」状态（不建议）。
