# 2026-10-20 让预设服从用户环境：服装库 / 张数 / 自然语言（v0.3.27）

## 一句话

用户实测发现两处「预设没按我们的设置来」：女性角色服装没走服装库、以及生成了用不到的
自然语言。前者是规范与任务协议互相打架，后者是当前启用的工作流开了 nl。已修规范、把
环境契约写进说明书，并把预设改成 nl 开关两侧都成立。

## 为什么

### 问题一：服装没按服装库

插件侧链路是通的：`runner.ts` 把 `closetLib` 渲染成【服装库】区块随请求下发，
任务协议（`autoTag/prompt.ts` 的 characterRule）也明写「女性角色的服装禁止自行创作，
只能从【服装库】挑一套整串照抄」。

但 `DEFAULT_COMFY_SPEC` 的「画面补全 §2」写着「人物可见时**优先完善服装版型、材质和配饰**」——
规范在 system，任务协议在 user，模型按 system 走，于是自己设计了 `white short-sleeve t-shirt`
之类的款式。**这是规范与协议的历史矛盾，与预设功能无关**，但预设原样继承了它。

另外，用户服装库的「日常」分类里是校服 / 雨衣 / 运动套装 / 奶牛装 / 女仆装，没有一件日常便装，
早餐场景确实无套可选 —— 这加剧了模型「自己写」的倾向。库内容需要用户自己补。

### 问题二：生成了 nl

`nl` 是否要求，取决于**当前 ComfyUI 工作流的「生成自然语言」开关**
（`activeComfyPreset().naturalLanguage`）。用户当前启用的是「工作流 3」（simple 模式，nl=on），
而他真正的「自用anima」是 nl=off。所以不是预设写错，是选错了工作流。

## 改了什么

### `src/state/settings.ts`（内置规范，两处 DEFAULT_COMFY_SPEC / DEFAULT_NAI_SPEC）

「人物可见时优先完善服装版型、材质和配饰」→
「人物可见时只补材质、褶皱与受光表现——服装款式不得自创（女性角色必须从请求里的【服装库】
挑一条整串照抄，男性角色按正文已写到的穿着写到部件级，详见任务协议）」

### `docs/presets/build-preset.mjs`（预设内容）

- 新增【服装来源｜优先级最高】一节：整串照抄、不得自创、不得以「场景不符」拒绝、
  没有【服装库】区块才按正文写、男性角色写到部件级。
- 张数改为「由用户设置决定（1–5，可能设了最少张数）」，不再假设固定张数。
- 三处依赖 nl 的写法（三分线位置、框中框/引导线、光线方位）改成
  `{{#nl}}…{{/nl}}` / `{{^nl}}…{{/nl}}` 双分支，关掉自然语言时改用 tag 表达。
- 思维链加一条自检：女性角色服装来自服装库且整串照抄。
- 产物改名 `分镜导演_ComfyUI_v2.json`（预设名不变，导入时按同名覆盖更新）。

### `文生图转换说明书/文生图转换说明书.md`

- 新增 **§1.1 运行环境契约**：张数、nl 开关、服装库、角色库、禁止项、JSON 字段，
  逐条给出「规范里应该怎么写」。
- 新增 **§5.5 标准作业流程**：世界书 + 说明书 → 任意 AI → JSON → 导入 → 跑一楼验证。
- 自检清单补三条：nl 条件段两侧成立、没写死张数、有服装库条款且无相反表述。

## 遗留 / 下一步

- **服装库缺日常款**：这是数据问题，不是代码问题。要让模型真的「只能从库里挑」，
  库里得先有一套能应付日常场景的便装，否则它只能在「照抄不合适的」和「自创」之间二选一。
- **nl 开关在渠道页**，不在设置页：工作流切换时容易忘。若长期不用 nl，
  建议把当前工作流的 nl 关掉，而不是依赖预设里的条件段。
- 预设长度已到 10040 字符（上限 12000）。再加内容就该做精简版了。

## 回滚

`settings.ts` 那句改回原文；`build-preset.mjs` 删掉【服装来源】一节与三条 nl 分支；
重新生成预设并重新导入即可。
