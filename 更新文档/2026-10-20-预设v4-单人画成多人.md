# 2026-10-20 预设 v4：单人画成多人、同名身份 tag（无代码变更）

## 一句话

实测单人场景被画成 2–3 个同一个人。根因不是模型「爱画多人」，而是 tag 里**根本没有人数 tag**
（`1girl, solo` 缺失），外加一条 `looking at another` 直接暗示画面里有第二个人。
v4 把「人数 tag 必写」升为硬性要求，并把 LoRA 角色的身份 tag 禁令写死。

## 证据（最新一楼 4 张图的 tag）

```
momoyuko, momoyuko \(momoyuko\), long black hair, purpke eyes, mole under mouth,
mature female, medium shot, (black nightgown:1.1), ... , looking at another, ...
```

- **没有 `1girl`，没有 `solo`** —— 四张图全部缺失。
- 第 4 张还有 `looking at another`（画面里只有一个人，却写「看向另一个人」）。
- `momoyuko \(momoyuko\)` 是把 LoRA 触发词首词当角色名、再复制成作品名。

## 为什么会出现

1. **人数 tag 缺失（决定性）**：Anima/SD 系没有 `1girl, solo` 时会自行决定人数；
   而这张 tag 里同一人的外貌被重复描述（触发词串已含发色瞳色 + 服装库整串 20 余词），
   模型倾向「多画几个相似的人」来覆盖这些描述。
2. **`looking at another`**：字面意思就是「看向另一个人」，等于给模型一个必须存在的第二人。
3. **`momoyuko \(momoyuko\)`**：Danbooru 的「角色 (作品)」形态常与多角色图鉴同现，进一步诱导。
4. 根子在**模型默认认为「单人不用写人数」**。v3 写了「单人裸写、不要 X on Y」，
   却没写「人数 tag 必须写」，模型把「裸写」理解成了「什么都不加」。

## 改了什么

### `docs/presets/build-preset.mjs`（产物 v4）

【单人 / 多人写法】新增开头三条硬性要求：

- 单人必须写 `1girl, solo`（男性 `1boy, solo`），放在最前（有 LoRA 触发词时紧跟触发词串之后）；
- 单人禁止 `looking at another`、`2girls`、`multiple girls`、`other girl`、`crowd`；
- 视线只能从 `looking at viewer / looking away / looking down / looking up / closed eyes` 里选。

【身份 tag 与 LoRA 触发词】补：带 LoRA 的角色一律不写身份 tag；禁止 `名字 \(同名\)` 形态；
不重复触发词已写明的部位特征。思维链补两条自检（19、20）。

### `文生图转换说明书/文生图转换说明书.md`

- §1.1 新增一行契约：单人必须写人数 tag，缺它是「单人画成多人」的头号原因。
- §6 自检清单新增两条。

## 怎么验证

```bash
node docs/presets/build-preset.mjs                 # comfySpec 11174 / comfyThinking 5717
npx vitest run src/state/presets.shipped.test.ts   # 2 passed
```

用户侧：导入 v4 → 跑一楼单人 → tag 开头应有 `1girl, solo`，且没有 `looking at another`。

## 遗留 / 下一步

- **comfySpec 已到 11174 字符（上限 12000）**，再也不能靠加规则解决了，下一步必须做精简版。
- 若 v4 仍缺人数 tag，说明「靠规范约束」这条路到头了，应改为**代码兜底**：
  在 `generate.ts` 出图前检查 tag，单人且无人数 tag 时补 `1girl, solo`（性别取自角色库/剧情），
  并在请求历史里标记「已兜底」。这条比继续加字数更可靠。
- `purpke` 是**用户角色库里的触发词拼写错误**（应为 `purple`），模型只是照抄；
  需要在「角色管理 → 倾城 → LoRA 触发词」里改，代码侧不用动。

## 回滚

删掉 v4 新增的三条硬性要求与两条自检，重新生成并导入 v3 即可。
