# 2026-10-20 修：重新生成头像不替换、图库里也看不到新图

## 一句话

头像文件名固定（`avatar.*`，同名覆盖），重新生成后 **URL 一个字都不变**，浏览器直接吃缓存，
`<img src>` 也没变化、Vue 不会重新加载 —— 于是看起来「点了生成没反应」。角色列表与图库两侧
的图片 URL 现在都带版本串。

## 为什么这么做

- 角色头像走 `uploadUserImage('柏宝绘_<角色名>', 'avatar', …)`，是**覆盖写**：
  磁盘上的图确实换了，但 `<img src="/user/images/柏宝绘_X/avatar.jpg">` 完全没变。
  浏览器对静态图片会缓存，页面里 src 不变也不会重新请求 → 一直显示旧图。
- 图库页同样按文件名拼 URL，所以**同名的头像**在图库里也还是旧那张，看上去像「没存进来」。
- 这个 bug 与生成链路无关（ComfyUI 那边其实每次都出新图，后台队列能看到）。

## 改了什么

| 文件 | 内容 |
| --- | --- |
| `src/pages/characters/index.vue` | 新增 `imageVersion` 版本号：每次头像上传成功后 `+1`，`imageSrc()` 拼 `?v=<版本>`；旧值 0 时保持无查询串（首次进页面不破缓存）。 |
| `src/pages/gallery/index.vue` | 新增 `loadVersion`：每次 `load()`（进页面/点刷新）取 `Date.now()` 作为版本串拼在图片 URL 上 —— 同名头像刷新即可见新图。 |
| `更新文档/README.md` | 版本与测试基线更新到 v0.3.35。 |

> 服务端 `/user/images/*` 是静态路由，查询串会被忽略，不影响取图。

## 怎么验证

```bash
node node_modules/vitest/vitest.mjs run     # 应仍全绿
node node_modules/vue-tsc/bin/vue-tsc.exe --noEmit   # 仅剩改动前既有报错
node node_modules/vite/bin/vite.js build    # v0.3.35
```

实机：
1. 角色列表点某个角色的「生成」→ 出图后格子立刻换成新图；
2. **再点一次同一角色** → 格子应再换一张（不再是「没反应」）；
3. 切到「图库」→ 该角色目录里的头像是最新那张；在图库里点右上刷新也会重新取图。

## 遗留

- 头像仍**只有一个文件**（同名覆盖），所以图库里不会累积多张历史头像。
  如果想要「每次生成都留一张」，需要改成带时间戳的文件名 + 放宽 `isAvatarFile`
  的正则（`^avatar[.-]`），属于产品取舍，没做。
- 若你在 ComfyUI 工作流里把种子写死成常量（不走 `%seed%`），同一提示词会画出一模一样的图，
  那是工作流问题，不是缓存。

## 回滚

去掉两处 `?v=` 拼接与两个版本号变量即可；数据无影响。
