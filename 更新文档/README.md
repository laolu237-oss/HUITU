# 更新文档 · 使用约定

> 给「下一个接手的 AI」看的入口。**每次改动都必须在这里新增一篇**，文件名 `YYYY-MM-DD-主题.md`，
> 不要改动历史篇目（历史是事实记录，不是待办清单）。

---

## 接手顺序（三步）

1. 读本文件的「当前状态速览」，确认版本、分支、测试基线；
2. 按日期倒序读 `更新文档/` 里最新的 1–2 篇，了解最近改了什么、为什么、还差什么；
3. 读仓根 `MAINTENANCE.md`（工程约定与坑）+ `文生图转换说明书/文生图转换说明书.md`（提示词预设格式）。

## 每篇更新文档的模板

```markdown
# YYYY-MM-DD 标题

## 一句话
这次改动解决了什么。

## 为什么这么做
决策与被否掉的方案（写清否决理由，避免下一个人重走一遍）。

## 改了什么
按文件列，标出关键函数/字段。

## 怎么验证
跑过的命令与结果。

## 遗留 / 下一步
没做完的、已知限制。

## 回滚
改回去要动哪几处。
```
