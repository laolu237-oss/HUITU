# 文生图转换说明书（柏宝绘 · 提示词预设）

> **怎么用**：把本文件 + 一本社区文生图世界书一起发给任意 AI，附一句：
> 「按这份说明书，把世界书转成 `bbi-prompt-preset` JSON，只输出 JSON，不要解释。」
> 拿到 JSON 后到 **柏宝绘 → 设置 → 自定义提示词 → 导入**。同名预设会覆盖更新。
>
> 本文件是**给外部 AI 的转换说明书**：把一本世界书（或任意来源的生图提示词规则）转换成
> 柏宝绘可导入的「提示词预设」JSON。
>
> 读法：先读 §1（目标系统的真实运行方式），再读 §2–§4（硬约束），最后按 §5 的规程改写。
> §6 是交付前的自检清单，§7 是一个完整示例。
>
> 适用版本：柏宝绘 **v0.3.27**（预设协议 `bbi-prompt-preset` v1）。本说明书只描述
> **导入格式与转换规则**，不描述插件内部实现。
>
> **维护约定**：本文件只在这个目录维护，不要在别处另存副本；每次改动同步记一笔到仓根 `更新文档/`。

---

## 0. 你的任务

输入：

- 一本世界书（JSON 或条目正文），或任意一份生图提示词规则文档；
- 本说明书。

输出：

- **一个 JSON 对象**，符合 §3 的格式，不得附带任何解释、前言、Markdown 代码围栏。

你不负责评价源书好坏，只负责**把它翻译成目标系统能执行的形态**，并按 §5 丢弃不兼容部分。
遇到无法判断的内容，写入 `notes` 数组，**不要自行补全**（见 §4 第 9 条）。

## 1. 目标系统的真实运行方式（转换前必读）

绝大多数社区「文生图世界书」是为**另一种执行者**写的。动手前必须理解柏宝绘的执行模型，
否则会把整本书塞进去，产出看起来通顺、跑起来必坏的预设。

| 维度 | 柏宝绘的实际行为 |
| --- | --- |
| **执行者** | 副 API（或跟随主 API），在**正文写完之后**单独发起一次请求 |
| **一次请求的产出** | 一个 JSON：本楼要画的图（0–N 张）+ 角色档案变更 |
| **谁写进聊天** | 插件写，不是模型写。模型不产出任何图片块、状态块或标记 |
| **角色一致性** | 由插件的**角色固定外貌库**负责：模型写角色名，插件机械替换为库中字段值 |
| **跨轮状态** | 存在插件侧（角色库 + 聊天历史），不存在于正文里的账本块 |
| **上下文来源** | 目标正文 + 最近 N 楼 + 角色库 + 已激活世界书条目 + 柏宝书记忆 |
| **发送频率** | **每层楼一次**。槽位里的每个字都会被重复计费，成本随楼层线性增长 |

由此得出三条铁律，转换时反复对照：

1. **不要教模型怎么输出块**。它不输出 `image###`、`<shot>`、`<ledger>`，只输出 JSON。
2. **不要教模型维护外观一致性**。它只需写出角色名；外貌来自角色库，模型改写会被覆盖。
3. **不要写跨轮账本**。没有「上一轮账本」这条通道；写进去的账本要么被插件当正文，要么被正则隐藏而副 API 读不到。

### 1.1 运行环境契约（写规范前必须对齐的事实）

下面每一条都是插件侧已经存在的机制。规范与它们冲突时，模型会按系统消息（也就是规范）执行，
把插件辛苦注入的档案盖掉 —— 这是实际踩过的坑。

| 既有事实 | 规范里应该怎么写 |
| --- | --- |
| **张数由用户设置决定**（1–5，可同时设最少与最多） | 写「按用户设置的上限取分最高的拍；设了最少 N 张就补足」。**不要写死张数**，写了会和设置打架 |
| **「生成自然语言」是工作流的属性**，可能开也可能关 | 依赖 nl 的写法放进 `{{#nl}}…{{/nl}}`，纯 tag 的替代写法放进 `{{^nl}}…{{/nl}}`。两种模式都必须成立 |
| **女性角色的服装只能来自【服装库】** | 必须明写：整串照抄、不得自创、不得以「与场景不符」为由拒绝。**绝不能写「主动完善服装版型」**——那会直接覆盖服装库 |
| **男性角色服装按正文生成** | 明写「写到部件级（版型 + 主色 + 关键部件），同一状态全楼复用」 |
| **角色固定外貌来自角色库** | 只写「照抄库中字段 / 只写角色名」，不要附锚点表，也不要要求模型自行维护 |
| **角色库里的 LoRA 触发词与库标记不是作品名** | 明写：身份 tag 的括号里只能是作品名；触发词（如 `adnim`）、`[locked]`、`[lora]:` 一律不得写进 tag，也不得转义成 `\(adnim\)` 这种形态 |
| **LoRA 触发词串原样保留** | 明写：触发词由插件拼入，**逐词保留、不改拼写、不删词**。即使其中出现看似笔误的词（如 `purpke eyes`），也不要「好心纠正」——那是作者自己调试过的组合。规范里不要要求模型改写触发词，也不要让它重复写触发词已含的特征 |
| **单人画面不需要绑定写法** | 明写：单人直接裸写特征/服装/表情；只有两人及以上才用 `X on Y` 绑到该角色的发色或瞳色。不写这条，模型会把多人绑定规则套到单人身上，产出 `white shirt on silver hair girl` 这类冗余 |
| **单人画面必须写人数 tag** | 明写：`1girl, solo`（男性 `1boy, solo`）是硬性要求，放在最前；并禁止 `looking at another`、`2girls`、`multiple girls` 等暗示第二个人的 tag。**缺人数 tag 是「单人画成两三个人」的头号原因** |
| **质量词、画师串、负面词由插件与工作流提供** | 规范里禁写，写了会双重叠加 |
| **输出是 JSON**：`tag` / `nl` / `negative` / `names` / `size` | 一律用字段名描述，不要用「第一行」「第二行」这类位置说法 |

> 服装是最容易翻车的一条：规范里只要出现一句「人物可见时主动完善服装」，
> 模型就会无视【服装库】自己设计款式。写规范时请把服装来源单独立一节，并声明优先级最高。

## 2. 五个槽位与职责边界

一份预设最多填五个槽位。**槽位之间不通用**：写错槽位等于没写。

| 槽位 key | 中文名 | 生效条件 | 职责 | 建议上限 |
| --- | --- | --- | --- | --- |
| `jailbreak` | 破限词 | 所有后端 | 降低副 API 拒答率。与内容规则无关，不要往里塞生图规范 | 800 字符 |
| `comfySpec` | ComfyUI 规范 | 默认后端 = ComfyUI | 定义 tag / nl 的**写法**：标签顺序、词表、互斥规则、画外裁剪、自检 | 6000 字符 |
| `comfyThinking` | ComfyUI 思维链 | 默认后端 = ComfyUI | 输出前的检查清单，作为 system 压在任务消息之后，解析时会被剥掉 | 3000 字符 |
| `naiV5Spec` | NAI 规范 | 默认后端 = NAI（4.5 / V5） | 定义 Base + Character Prompts 的分工与写法 | 6000 字符 |
| `naiV5Thinking` | NAI 思维链 | 默认后端 = NAI（4.5 / V5） | 同 ComfyUI 思维链，但槽位块对应 `characters[]` 协议 | 3000 字符 |

规则：

- **只填与 `backend` 对应的槽位**，另一后端的槽位留空串（空串 = 回落内置默认）。
- `jailbreak` 可留空；留空时用内置默认。
- 规范与思维链**必须配对**：思维链里要求填的每个字段，必须在同后端的规范里有判据。
  只给思维链不给规范，模型会被要求填它从没学过的内容。
- 两份规范**不得互相引用**（「见 NAI 规范」这种写法在另一后端下会指向空）。

## 3. 输出格式

```json
{
  "schemaVersion": 1,
  "kind": "bbi-prompt-preset",
  "name": "预设名（中文，20 字以内）",
  "backend": "comfyui",
  "basedOn": "来源书名或文档名",
  "prompts": {
    "jailbreak": "",
    "comfySpec": "……",
    "comfyThinking": "……"
  },
  "notes": [
    "无法判断或已被丢弃的内容，逐条说明原因"
  ]
}
```

字段约束：

- `schemaVersion`：固定为数字 `1`。
- `kind`：固定为字符串 `"bbi-prompt-preset"`。
- `backend`：只能是 `"comfyui"` 或 `"nai"`。
- `basedOn`：来源标识，便于回溯；可留空串。
- `prompts`：键只能是 `jailbreak` / `comfySpec` / `comfyThinking` / `naiV5Spec` / `naiV5Thinking`；
  未使用的槽位**可以省略**，省略等价于空串。值必须是纯文本字符串（`\n` 正常转义）。
- `notes`：字符串数组，可省略。**这是你唯一被允许表达不确定性的地方。**

### 3.1 预设是整体替换，不是叠加

槽位非空即**完全取代**插件内置的规范与思维链（`backendPromptSpec` 的回落只发生在空串时）。
因此：**不要写「按内置规范」这类引用**——内置那时已经不在场了。

正确做法是把内置规范里仍然需要的硬约束**自带一份**。以 ComfyUI 为例，至少要覆盖：
tag 的排列次序、同人角色身份 tag 与括号转义、多人画面的特征绑定、景别与画外 tag 的一致性、
画面语言（镜头/光线/色调）由模型主动补全、原创角色不写身份 tag。

> 仓内 `docs/presets/build-preset.mjs` 演示了稳妥做法：从源码抽取内置文本原文，再追加增强段落。
> 这样既保留内置约束，又能加入自己的分镜层，且内置更新后重跑脚本即可同步。

### 3.2 导入时会被直接拦下的写法

| 拦下的内容 | 原因 |
| --- | --- |
| `kind` / `schemaVersion` 不对 | 不是本格式的文件 |
| `backend` 与所填槽位不匹配（如 backend=comfyui 却只填 NAI 槽位） | 导入后「成功但不生效」，最难排查 |
| 未知槽位键（拼错 `comfySpecc`） | 内容会被静默丢弃 |
| `{{user}}`、`{{char}}`、`{{getvar}}`、`<% %>`、`<START>` | 槽位不做宏替换，会原样发给模型 |
| `{{#nl}}` 与 `{{/nl}}` 不成对、或嵌套 | 解析端是非贪婪正则，会静默吞掉半段文本 |
| `{{nl}}` 出现在 `comfySpec` 以外的槽位，或出现多次 | 只在该槽位展开，别处无效 |
| 单槽位超过 12000 字符 | 基本是把整本书塞了进来 |
| 行首出现 `image###` / `<shot>` / `<ledger>` / `<bbi_image>`，或用「输出/写入」类动词要求模型写它们 | 会诱导模型产出主模型侧协议 |

注意最后一条的边界：**在否定句里提到**（「不得包含 `<bbi_image>` 标签」）或**把历史标记当线索引用**
（「历史 `<bbi_image>` 只作连续性线索」）是允许的，不会拦。

## 4. 硬约束（违反任一条即报废）

1. **不得出现块协议**：`image###`、`<shot>`、`<ledger>`、`<bbi_image>`、`<tag>`、`<nl>`、`<size>`。
2. **不得要求模型输出 Markdown 代码块或 JSON 之外的说明**；输出协议由插件固定，规范只管内容写法。
3. **不得写质量词、画师名、年份、负面词**。这些由后端面板与工作流预设提供，写进规范会双重叠加。
4. **不得使用 ST 宏**：`{{user}}`、`{{char}}`、`{{getvar::}}`、`{{setvar::}}`、`<% %>`、`<START>`。
   这些文本不经宿主宏替换，会被字面发给模型。
5. **只允许一种宏**：自然语言条件段 `{{#nl}}…{{/nl}}`、`{{^nl}}…{{/nl}}`，且必须成对闭合。
   `comfySpec` 另允许一个 `{{nl}}` 占位（最多一次）。
6. **不得教模型维护角色固定外貌**。允许且应当写「外貌以角色库为准、逐字照抄库中字段」，
   但不得写「按下面的锚点复制」并附一份锚点表——那份表属于角色库，不属于规范。
7. **不得写张数、尺寸、模型、采样器**。这些是用户面板设置，规范里出现会与设置打架。
8. **不得引用源书内部的条目编号**（「见条目 04」「条目 05 的格式」）。导入后这些编号不存在。
9. **不确定必须上报**：源书里含混、自相矛盾、或依赖源系统特有机制的内容，写入 `notes`，
   不得自行编造一个「合理」的版本。
10. **不得保留源书的元指令**（配置面板、开关说明、一次性生成器、安装说明）。

## 5. 转换规程

### 5.1 先判定源书类型

| 源书类型 | 特征 | 处理 |
| --- | --- | --- |
| **A. 主模型分镜代理系统** | 要求模型在正文里输出 `image###` / `<shot>` / `<ledger>`，用账本跨轮记状态 | 按 §5.2 大改：只提炼规则层 |
| **B. 纯规则书** | 只讲怎么写 tag、怎么构图、词表 | 按 §5.3 直接改写 |
| **C. 画风 / 词表书** | 主要是画师串、质量词、负面词、风格词 | **不要转成预设**。在 `notes` 里说明应改用「画师串预设」 |
| **D. 角色 / 世界观设定** | 角色外貌、地点、剧情 | **不要转成预设**。这属于角色库与世界书本职 |

### 5.2 A 类的丢弃清单（重要）

以下内容在柏宝绘里**没有承载位置**，必须整段丢弃，并在 `notes` 里写明：

| 源书内容 | 处理 | 原因 |
| --- | --- | --- |
| `<ledger>` 状态账本及其更新规则、示例 | 丢弃 | 无跨轮账本通道；状态由插件侧维护 |
| `<shot>` 分镜计划行 | 丢弃 | 计划由 `images[]` 承载，重复 |
| `image###` 块结构与行序 | 丢弃，改写为 JSON 字段分工 | 输出协议不同 |
| 「回复结构」「每轮回复顺序」 | 丢弃 | 那是主模型的正文排版，与副 API 无关 |
| 配置面板（张数、标签量、开关） | 丢弃 | 张数等是用户面板设置 |
| 角色锚点字段表、锚点生成器 | 丢弃 | 角色库已负责，且有自动建档（`changes`） |
| 场景锚点字段表 | 丢弃 | 无场景库；只保留「场景细节取自正文 + 三层纵深」 |
| 世界书条目设置说明（位置、深度、触发词） | 丢弃 | 导入后不依赖世界书 |

以下内容**应当保留并改写**：

| 源书内容 | 改写方向 |
| --- | --- |
| 硬规则（不加戏 / 不写否定 / 归属明确 / 一图一事 / 画外不写 / 状态连续） | 原样保留，措辞改为「每张图」而非「每个 image 块」 |
| 选拍打分表、张数节奏模板 | 保留打分表；节奏模板改为「按用户设置的上限取前 N 个拍子」 |
| 镜头类型表、构图法则、光线设计、轴线规则 | 保留，是本书的核心价值 |
| 景别 / 视角 / 焦点 / 效果 / 表情 / 肢体词表 | 压缩保留：只留清单，删掉模板句与示例 |
| 画外裁剪表、冲突表 | 原样保留，价值最高 |
| 质检清单 | 保留并改写：删掉与 `<shot>`、`<ledger>` 相关的条目 |
| 反例对照 | 压缩为「常见错误：错误写法 → 正确写法」，每条一行 |
| 场景句（自然语言）写法 | 保留，直接对应 `nl` 字段 |

### 5.3 改写为 JSON 字段分工

源书里「一个 image 块分七行」的结构，在柏宝绘里对应如下字段：

| 源书部分 | 目标字段 | 说明 |
| --- | --- | --- |
| 安全分级 + 人数 + 场景 + 镜头 + 一般标签 | `tag`（ComfyUI）/ Base `tag`（NAI） | 全局内容，不含单个角色的外貌与动作 |
| 每个角色一行 | NAI：`characters[]` 每项一个；ComfyUI：并入 `tag` 但按角色分段书写 | NAI 必须分块，ComfyUI 靠行内顺序与归属词区分 |
| 英文场景句 | `nl` | 仅「生成自然语言」开启时要求 |
| 角色档案变更 | `changes[]` | 只报永久变化与建档，临时状态不进 |

规范里描述这些字段时，用**字段名**（`tag` / `nl` / `characters[]` / `changes[]`），
不要用「第一行」「第二行」这类位置说法——位置在 JSON 里不存在。

### 5.4 长度控制
槽位每楼都发。按以下优先级删减，直到落进建议上限：

1. 删模板句与完整示例（规则本身已足够）；
2. 词表只留清单，删解释；
3. 合并同义规则；
4. 最后才删规则——但「冲突表」「画外裁剪表」「硬规则」永远不删。

给出两档时，用 `notes` 说明差异（如「精简版已删词表附录，需要时改用完整版」）。

### 5.5 标准作业流程（用户侧）

以后拿到任何一本社区文生图世界书，都按这五步走，不需要再改代码：

1. **准备两样东西**：目标世界书（`.json` 原文件最佳，或条目正文）+ 本说明书。
2. **交给任意 AI**，只说一句：
   「按这份说明书，把世界书转成 `bbi-prompt-preset` JSON，只输出 JSON，不要解释。」
3. **拿到 JSON 直接导入**：柏宝绘 → 设置 → 自定义提示词 → 导入。
   导入器会校验；不合格会指出**具体槽位与原因**（如「槽位 comfySpec 含 ST 宏」「backend 与槽位不匹配」）。
4. **导入后先跑一楼**，只看三件事：
   张数是否符合设置、女性角色的服装是否来自服装库、双人画面是否串色。
5. **不满意就改 JSON 再导入**（同名会覆盖更新），不要手改槽位后忘了点「保存」。

> 第 3 步能拦住绝大多数错误，但拦不住「规则写得很顺、模型却不照做」。
> 所以第 4 步不能省 —— 校验器只管格式，不管效果。

## 6. 交付前自检

逐条勾选，任一不通过就改到通过：

- [ ] 输出是**单个 JSON 对象**，无前言、无代码围栏、无注释。
- [ ] `schemaVersion` = 1，`kind` = `bbi-prompt-preset`，`backend` 合法。
- [ ] `prompts` 的键都在白名单内，值与 `backend` 匹配。
- [ ] 全文搜索 `image###`、`<shot>`、`<ledger>`、`<bbi_image>`：**零命中**。
- [ ] 全文搜索 `{{user}}`、`{{char}}`、`{{getvar`、`<%`、`<START>`：**零命中**。
- [ ] `{{#nl}}` 与 `{{^nl}}` 的总数等于 `{{/nl}}` 的数量。
- [ ] 没有质量词、画师名、年份、负面词清单。
- [ ] 没有张数、尺寸、模型名、采样器参数。
- [ ] 没有「见条目 N」这类内部编号引用。
- [ ] 没有引用「内置规范」——预设会整体替换它，引用等于没有。
- [ ] 内置规范里仍然需要的硬约束已自带（身份 tag 转义、多人绑定、景别一致性等）。
- [ ] `backend` 与所填槽位一致（comfyui ↔ comfySpec/comfyThinking，nai ↔ naiV5Spec/naiV5Thinking）。
- [ ] 与 nl 相关的内容都包在 `{{#nl}}` / `{{^nl}}` 里，开关两侧都能独立成立。
- [ ] 没有写死张数、尺寸、模型名；张数只说「按用户设置的上限/下限」。
- [ ] 写了「女性角色服装只能来自【服装库】整串照抄」，且全文没有「主动完善服装」这类相反表述。
- [ ] 写了「单人直接裸写、两人及以上才用 `X on Y` 绑定」，并写了「同一 tag 不重复」。
- [ ] 写了「身份 tag 括号里只能是作品名，LoRA 触发词与库标记不算」。
- [ ] 写了「单人画面必须写 `1girl, solo`，并禁止 `looking at another` 等暗示第二个人的 tag」。
- [ ] 写了「带 LoRA 的角色不写身份 tag，禁止 `名字 (同名)` 这种编造形态」。
- [ ] 写了「LoRA 触发词逐词原样保留，不纠正拼写、不删词、不重排」。
- [ ] 规范与思维链**配对**：思维链要求的每个字段，规范里都有判据。
- [ ] 每个槽位长度不超过建议上限；超出时已按 §5.4 删减。
- [ ] 所有无法判断的内容都写进了 `notes`，没有自行补全。

## 7. 示例（节选）

以下是一份由「主模型分镜代理系统」类世界书改写出的 `comfySpec` 片段，仅示范写法与口径，
不是完整预设：

```json
{
  "schemaVersion": 1,
  "kind": "bbi-prompt-preset",
  "name": "分镜导演·精简",
  "backend": "comfyui",
  "basedOn": "示例来源",
  "prompts": {
    "comfySpec": "你是剧情画面的分镜设计者。为每张图决定：画哪一拍、用什么镜头、画面里有什么。\n\n【选拍】按视觉价值打分，取分最高的若干拍（数量由用户设置决定）：情绪峰值 +3、肢体动作高点 +3、场景/时间/天气转换 +2、服装或外观变化 +2、新角色或关键物件登场 +2、关系转折 +2、空间位置改变 +1、纯对话 +0。相邻两拍不同时入选；至少一张取自正文后三分之一。分数都很低时改用镜头补位：正反打、环境插入、物件插入、反应镜头。\n\n【一图一事】一张图只有一个景别、一个主视角、一个焦点、一个主要动作。\n\n【互斥】景别互斥、视角互斥、眼部互斥、嘴部互斥、人数互斥、服装互斥、发型互斥、光线互斥、朝向互斥：命中任一对，立刻删掉其中之一。\n\n【画外裁剪】close-up 只保留头颈肩，删掉下装与鞋袜；upper body 删掉小腿与鞋袜；from behind 删掉瞳色与嘴部表情；pov 不写入镜者本人的外观。\n\n【不写否定】不写 no hat、without shoes；要表达没有，就写它的对立状态（barefoot）或干脆不提。\n\n【nl】英文短句，一句一个主语，不超过 25 词；用名词不用代词；只写看得见的东西；全部肯定句；位置用 left / right / center / foreground / background。",
    "comfyThinking": "输出前逐项检查：人数标签与入镜人数一致；每个外观与服装标签都有明确归属；景别、视角、焦点各只有一个且不冲突；画外裁剪已执行；没有否定表达；没有正文里没出现的角色、道具、地点；nl 有位置、有动作、有纵深；没有质量词、画师、年份、负面词。发现问题直接改，不输出检查过程。"
  },
  "notes": [
    "源书的状态账本、分镜计划行与 image 块结构已丢弃：目标系统无对应通道，状态由插件侧角色库维护。",
    "源书的角色锚点表与锚点生成器已丢弃：外貌由角色库提供，模型只需写出角色名。",
    "源书的场景锚点表已丢弃：目标系统无场景库，场景细节改为从正文抽取。"
  ]
}
```

## 8. 一页速查

- 执行者：副 API，一次请求出一份 JSON，**不写聊天**。
- 五个槽位：`jailbreak` / `comfySpec` / `comfyThinking` / `naiV5Spec` / `naiV5Thinking`。
- 只填与 `backend` 匹配的槽位，另一后端留空。
- 规范管「怎么写」，思维链管「输出前查什么」，两者必须配对。
- 丢弃：块协议、账本、锚点表、配置面板、条目编号引用。
- 保留：选拍、镜头、构图、光线、互斥表、裁剪表、硬规则、`nl` 写法。
- 不确定 → `notes`，不要编。
